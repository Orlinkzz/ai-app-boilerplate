Satu AGENTS.md untuk banyak AI coding tool

Dari ide sampai aplikasi dipakai orang, dengan AI coding tool apa pun. Peta jalan bertahap, prompt siap pakai untuk tiap tahap, satu file aturan untuk semua AI, plus git hook dan CI yang menjaga proyekmu tetap rapi.

Use this template Mulai tutorial

Masalahnya: tiap AI tool punya file aturan sendiri

Claude Code membaca CLAUDE.md, Gemini CLI membaca GEMINI.md, Cursor punya .cursor/rules, Copilot punya copilot-instructions.md. Menyalin aturan yang sama ke semuanya cepat berantakan.

Satu sumber

Semua aturan ditulis di AGENTS.md. Banyak tool membacanya langsung.

Stub, bukan salinan

CLAUDE.md dan GEMINI.md hanya berisi baris import ke AGENTS.md, jadi tidak ada yang bisa melenceng.

Dijaga otomatis

Pre-commit hook dan CI memeriksa agar semuanya tetap sinkron dan tidak ada .env yang ikut ter-commit.

Tutorial: dari ide sampai aplikasi dipakai orang

Delapan langkah, mengikuti tahap di docs/ROADMAP.md. Bingung sedang di mana? Jalankan make status. Semua perintah bisa disalin dengan tombol Salin.

  1. Siapkan prasyarat

    Kamu butuh git, make, bash, dan satu AI coding tool. Toolchain stack (Node.js, Bun, Go, PHP) baru dibutuhkan setelah stack dipilih di langkah 4.

    Pengguna WindowsGunakan WSL (disarankan) atau Git Bash. make dan script bash tidak jalan di PowerShell biasa. Panduan singkatnya ada di README, bagian Pengguna Windows.

  2. Buat repo dari template

    Klik Use this template di GitHub, clone repo barumu, lalu aktifkan git hook dan cek posisimu:

    make setup
make status

    Hook akan menolak commit file .env dan memastikan stub CLAUDE.md/GEMINI.md tetap valid. make status memberi tahu tahap proyekmu dan langkah berikutnya.

  3. Tentukan arah dulu: PRD dan arsitektur

    Jangan langsung minta AI menulis kode. Tanpa arah yang jelas, AI akan menebak, dan tebakannya berubah tiap sesi.

    TahapPromptHasil
    0. Ide00-idea-to-prd.mdAI mewawancaraimu, lalu menulis draf docs/PRD.md
    1. PRD01-review-prd.mdKritik dan pemotongan scope (MVP maksimal 5 fitur)
    2. Arsitektur02-design-architecture.mddocs/ARCHITECTURE.md + rekomendasi stack

    Ingin melihat seperti apa hasil yang baik? Lihat examples/: aplikasi kas kelas tanpa backend, dan aplikasi kasir (POS) warung dengan login dan database.

  4. Terapkan stack yang dipilih

    Terapkan stack hasil tahap arsitektur. Ini mengisi AGENTS.md, target Makefile, dan setup CI sekaligus. Belum yakin? Lihat panduan memilih stack di Stack.

    make stacks
make init STACK=react

    Ingin melihat perubahannya dulu tanpa menulis apa pun?

    bash scripts/init-stack.sh react --dry-run

    Perintah ini aman dijalankan ulang dan bisa dipakai untuk berganti stack. Tidak cocok dengan stack yang tersedia? Lewati langkah ini dan isi target deps/dev/test/lint/build di Makefile sendiri.

  5. Isi identitas dan buat proyeknya

    Buka AGENTS.md, isi Nama dan Tujuan, lalu hapus blok TEMPLATE-NOTE. Ganti nama pemilik di LICENSE.

    Template tidak membuatkan kode aplikasi. Jalankan perintah scaffold untuk stack-mu (lihat tabel Stack), lalu cek:

    make lint
make test
make build
    Gagal itu normal di awalTarget yang belum terisi sengaja gagal agar CI tidak hijau palsu. Membuatnya hijau adalah task pertamamu (T-001). Untuk React dan Svelte, tambahkan Vitest dulu (npm i -D vitest dan script "test": "vitest").

  6. Commit, push, dan biarkan CI bekerja

    git add -A
git commit -m "chore: init project"
git push -u origin main

    CI menjalankan make check-ai (aturan AI sinkron) dan make lint + make test. Jika kamu membuat repo lewat clone tanpa template, tambahkan remote dulu: git remote add origin <url-repo-kamu>.

  7. Pecah jadi task, kerjakan satu per satu

    Isi docs/TASKS.md dengan 03-break-into-tasks.md, lalu ulangi loop ini untuk setiap task:

    LangkahPromptHasil
    Rencana04-plan-task.mdRencana per task, belum menulis kode. Kamu yang menyetujui
    Implementasi05-implement-task.mdKode + test sesuai rencana yang disetujui
    Review06-review-code.mdTemuan bug dan test yang kurang (sebaiknya di sesi AI baru)
    Keamanan07-security-audit.mdAudit berbasis OWASP Top 10 untuk task yang menyentuh login, input, atau data pribadi
    Debug (kapan saja)08-debug.mdAkar masalah, lalu perbaikan minimal

    Satu task, satu sesi AI, satu commit kecil. Kamu tetap arsiteknya: baca dan review kode yang dihasilkan sebelum merge.

  8. Rilis, lalu belajar dari pengguna

    Setelah semua task MVP selesai, jalankan audit keamanan untuk seluruh aplikasi, lalu 09-deploy.md untuk memilih hosting dan mengikuti checklist rilis. Setelah ada pengguna, olah masukan mereka dengan 10-iterate.md dan kembali ke loop task.

Tool versi lama (opsional)

Jika tool-mu belum membaca AGENTS.md, aktifkan salinan di .ai-sync-targets (hapus tanda # di barisnya), lalu:

make sync-ai
make check-ai

Pengaman otomatis

Pre-commit hook

Menolak .env, menjaga stub tetap valid, dan menyinkronkan salinan legacy bila aktif. Bisa dilewati dengan --no-verify, tapi CI tetap menangkapnya.

CI

Job ai-rules memeriksa sinkronisasi. Job quality menjalankan lint dan test di repo turunan.

Tes mandiri

make selftest menguji script sync, hook, dan semua template stack (untuk kontributor template).

Pertanyaan yang sering muncul

Saya punya ide tapi bingung mulai dari mana. Harus ngapain?

Jangan mulai dari kode atau dari memilih stack. Mulai dari prompts/00-idea-to-prd.md: AI akan mewawancaraimu dan menulis PRD. Setelah itu ikuti tahap di docs/ROADMAP.md. Kapan pun bingung, jalankan make status untuk melihat tahapmu sekarang dan langkah berikutnya.

Apa itu AGENTS.md dan kenapa dipakai?

AGENTS.md adalah file instruksi proyek untuk AI coding agent. Dengan satu file sebagai sumber, kamu tidak perlu menulis aturan yang sama berulang-ulang untuk tiap tool. Banyak tool membacanya langsung. Claude Code membacanya lewat CLAUDE.md yang berisi @AGENTS.md, dan Gemini CLI lewat GEMINI.md yang berisi @./AGENTS.md.

Apakah template ini bekerja di semua AI tool?

Template ini dirancang berdasarkan dokumentasi resmi tiap tool, tetapi belum diuji langsung di semuanya. Dukungan juga bergantung versi tool. Jika ada yang tidak bekerja, buka issue di repository.

Kenapa make lint dan make test gagal setelah saya clone?

Itu disengaja. Target dev, test, lint, dan build gagal sampai kamu mengisinya, supaya CI tidak hijau palsu. Jalankan make init STACK=nama-stack untuk mengisinya otomatis, atau isi Makefile sendiri.

Apakah bisa dipakai di Windows?

Bisa, dengan WSL atau Git Bash, karena template memakai make dan bash. Di Windows izin eksekusi script bisa hilang saat commit; perbaiki dengan git update-index --chmod=+x pada file script.

Apakah saya wajib memakai stack yang tersedia?

Tidak. Template stack hanya mempercepat awal. Kamu bisa mengisi target di Makefile dan bagian stack di AGENTS.md sendiri untuk stack apa pun.

Bagaimana dengan versi tool AI yang lama?

Versi lama yang belum membaca AGENTS.md bisa memakai salinan opsional. Aktifkan barisnya di file .ai-sync-targets lalu jalankan make sync-ai.
